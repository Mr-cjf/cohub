# 发版规范

> **规范源**: 团队约定（oh-my-opencode-cohub）
> **生效范围**: 所有版本发布
> **权威性**: 本文件是发版流程的唯一权威源；`packages/oh-my-opencode-cohub/AGENTS.md`、`.rules/06-dsh-plugin-dev.md`、`docs/npm-release-setup.md`、`.opencode/skills/Git提交与发版/SKILL.md` 均为转发摘要，冲突时以本文件为准

## 执行清单

- [ ] 发版前必须更新 `CHANGELOG.md`，按 Keep a Changelog 格式记录本次变更
- [ ] CHANGELOG 条目必须区分：新增 / 修复 / 变更 / 移除
- [ ] 逐个待发布包核对 README.md：首屏版本锚点（「本文对应 vX.Y.Z」）已改为目标版本号
- [ ] 按本次待发布变更核对 README 正文：涉及的功能、命令、配置项、安装步骤已同步；若正文无需变更，须在发版 commit message 中说明理由
- [ ] CHANGELOG 提交与版本号提交必须分开（先 docs: 再 chore:）
- [ ] 版本号遵循 SemVer：主版本.次版本.修订号
- [ ] 打 tag 前必须确认目标版本号未被占用：`git tag -l "opencode-vX.Y.Z"` 与 `git ls-remote --tags origin "refs/tags/opencode-vX.Y.Z"` 必须均为空（其他分支可能已发布过该版本号）
- [ ] `package.json` 中 `repository.url` 必须指向正确的 GitHub 仓库地址（CI 使用 `--provenance` 校验依赖此项）
- [ ] 推送 tag 前确认所有代码已提交并推送到 GitHub
- [ ] 每次发版后必须按「安装安全」重新安装并重启 OpenCode 验证

## 发版流程

1. **更新文档（README）** — 修改各待发布包 README.md：首屏版本锚点改为目标版本号；按本次变更同步功能/命令/配置/安装说明。正文无需变更时，在本步留一句理由备查
2. **更新 CHANGELOG.md** — 新增版本条目，填写改动内容
3. **提交 CHANGELOG** — `git add CHANGELOG.md && git commit -m "docs: 更新 CHANGELOG vX.Y.Z"`（独立 docs commit）
4. **提交源码变更** — 修复/新增代码独立提交（`fix:` / `feat:`）；同一 PR 内 docs、源码、chore 三个 commit 各自独立
5. **手动更新版本号** — 直接编辑 `package.json` 与 `package-lock.json` 的 `version` 为 X.Y.Z，`git commit -m "chore: 版本号 X.Y.Z"`；**不使用 `npm version`**（避免其自动 commit / 打 tag / 触发 lifecycle）
6. **合并到 main** — PR 合并后先核实 main 上的目标 commit SHA：`git fetch origin` + `git rev-parse origin/main`
7. **确认版本号未被占用** — 执行 `git tag -l "opencode-vX.Y.Z"` 与 `git ls-remote --tags origin "refs/tags/opencode-vX.Y.Z"`，**两者都必须为空**。若已被占用（其他分支可能已发布过该版本号），必须改用更高版本号；**严禁删除、移动或覆盖已有 tag**。
8. **打 annotated 标签并推送** — 对已核实的 main SHA 打标签：`git tag -a "opencode-vX.Y.Z" -m "release X.Y.Z" <main-SHA>`；确保使用 SSH remote（`git@github.com:...`），`git push --follow-tags`
9. **发布由根 workflow 执行** — 仅根仓库 Publish to npm workflow（OIDC 身份）执行发布，**不在本地运行 `npm publish`**
10. **重装验证** — 按下方「安装安全」执行

> 提示：版本号按 SemVer 选择增量（`patch` / `minor` / `major`）。

## 安装安全

- **包 CLI 只做隔离 HOME 验证**：`bunx oh-my-opencode-cohub install` 等包自带 CLI 仅在隔离 HOME 环境中验证，**不在真实 HOME 上整文件重写配置**
- **真实 HOME 使用官方插件命令**：`opencode plugin oh-my-opencode-cohub@<精确版本号> --global --force`
- **先时间戳备份**：执行前先对 `opencode.json`、`tui.json` 做时间戳备份，其余字段保持不变
- **重启边界**：新版本经重启 opencode 后生效；重启仅作用于插件/会话加载，不修改任何用户配置文件

## CHANGELOG 格式

```markdown
## [版本号] - YYYY-MM-DD

### 新增
- 新功能描述

### 修复
- Bug 修复描述

### 变更
- 行为变更描述

### 移除
- 已删除的内容
```

## CR 检查清单

- [ ] CHANGELOG.md 是否在发版前更新？
- [ ] 版本号是否符合 SemVer？
- [ ] CHANGELOG 提交和版本号提交是否分开？
- [ ] 发版后是否重新安装验证？
- [ ] 待发布包的 README.md 首屏版本锚点是否与 package.json 的 version、CHANGELOG 本次条目版本号三者一致？正文受影响的说明是否已同步（或已记录无需变更的理由）？
